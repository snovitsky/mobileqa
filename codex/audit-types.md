# Виды проверки

- Документационный аудит: сравнить профиль с manifest/исходниками, проверить ссылки, статус и актуальность. Валидатор не оценивает реальное поведение браузера.
- Проверка поведения: вручную пройти два режима синхронизации из [checks.md](checks.md); отдельно формы, навигация, ошибки готовности и Stop.
- Проверка разрешений: трассировать prepare/cleanup, host permissions и DNR в background, handshake в bridge; учитывать [risk-zones.md](risk-zones.md).
- Проверка данных: проверить storage keys и поля диагностики по [data-map.md](data-map.md), без выгрузки реальных секретов.
- Проверка профилей: сравнить размеры с целью QA; сведения о популярности устройств требуют самостоятельной внешней проверки, если задача касается статистики.

Инициализация 2026-10-06 — анализ исходников и документации, с ограниченными статическими проверками. Полный security audit, реальное тестирование Chrome и независимая проверка внешних ссылок не проводились.

Обновление 2026-10-08 добавило анализ package/lock, scripts, двух браузерных тестов, CI и CONTRIBUTING/PROTOCOL. Наличие тестовых assert в коде не означает, что тесты успешно выполнены на этом компьютере; реальные результаты — в checks.md/changelog.md. Remote branch protection описана по CONTRIBUTING, не проверена через GitHub settings API.
