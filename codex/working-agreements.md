# Рабочие договорённости

- Общение и новая документация на русском; API, команды и пути сохраняют оригинальное написание.
- Коммиты: Conventional Commits с русским описанием и обязательным подтверждением после полного pre-flight. Правило пользователя применяется к каждому коммиту.
- Чужие изменения не включать без отдельного разрешения; не создавать дополнительные backup/dump/bak/snapshot-файлы.
- HTTPS Git на этом Windows-компьютере выполнять сразу вне песочницы штатным механизмом require_escalated. Не обходить отказ; это не разрешение на push.
- Не записывать секреты, значения паролей, cookies и реальные credential values в рабочую документацию.
- Репозиторий описан исходными правилами как публичный: не коммитить токены, .env, клиентские выгрузки и персональные данные. Фактическую видимость GitHub при переносе документации отдельно не проверяли.
- Сохранить назначение Basic: проверка сайтов и синхронизация экранов без Metrica, внешних API и клиентских данных. Не искать/использовать доступы других проектов, старых папок, системных конфигураций или истории чатов; не ссылаться на такие источники.
- Только main, отдельный клон на исполнителя, без force push и обязательных PR. Перед задачей pull --ff-only; перед push npm test и npm run build. Наличие direct push не отменяет подтверждение коммита и согласование отправки.
- Задачи и пересечения файлов согласовать в Issue. Крупный рефакторинг отделять от функциональных изменений. Пользовательские credentials, .env, выгрузки и абсолютные пути компьютера не добавлять в код/тесты.
- Не расширять permissions без явной инструкции; соблюдать codex/api-map.md. Автотесты работают только с локальными fixture и отдельным Chromium profile, без отправки форм/целей на рабочих сайтах.
- Общение по-русски; английские сообщения пользователя проверять как репетитор согласно полученному AGENTS.md.
- Не фиксировать постоянную роль пользователя. Отчёты должны быть понятны и техническому, и нетехническому читателю.
- Разрешение на аудит/обновление документации само по себе не разрешает исправление кода приложения, коммит и push. Историю конкретных задач вести в changelog, а не в текущих договорённостях.
- Вся подробная документация и справочные материалы — в codex/. В корне только AGENTS.md с правилами агента и краткий README.md со ссылками. Не создавать дублирующие PROTOCOL/CONTRIBUTING и копии справочников в extension/. GitHub templates остаются в .github/ как служебные формы GitHub.
