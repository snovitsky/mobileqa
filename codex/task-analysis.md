# Анализ задачи перед изменениями

1. Проверить `git status --short --branch` и применимые AGENTS.md. Отделить изменения пользователя.
   Учитывать codex/workflow.md: собственный клон, только main, pull --ff-only перед работой, согласование пересечений в Issue. Для контрактов читать codex/api-map.md.
2. Определить режим: следование основной вкладке или управление из iframe. У них разные сборщики событий; изменения одного не гарантируют изменения другого.
3. Проследить действие: DOM → desktop-source/runtime/background/panel либо bridge/postMessage/panel → bridge/apply → DOM.
4. Уточнить домен, разрешения, режим встраивания, число панелей, состояние готовности и синхронизации. Это влияет на результат больше, чем название модели устройства.
5. Выбрать проверки из [checks.md](checks.md). Статическая проверка не заменяет browser smoke.
6. При новых знаниях обновить профиль и историю; сомнения записать в [open-questions.md](open-questions.md).

Для нового профиля устройства нужны реальные основания CSS-размеров. Содержимое `codex/device-sources.md` — существующие заявления проекта, не независимая проверка статистики.
