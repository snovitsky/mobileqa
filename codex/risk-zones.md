# Риски и ограничения реализации

Факты ниже проверяются по исходникам; результаты реально выполненных регрессий отдельно в [checks.md](checks.md). Наличие теста не доказывает отсутствие дефектов на любом сайте.

| Зона | Ограничение |
|---|---|
| Реальные действия | Стандартный submit/replay guard не блокирует произвольные click/input handlers и отложенные запросы сайта на зеркалах. На рабочих сайтах автоматические формы не отправлять. |
| Password/file | Оба content scripts исключают их при capture/apply; регрессия должна охватывать оба направления. Значения обычных полей передаются для replay, но не записываются в trace. |
| Заголовки | Prepare снимает всю CSP, CSP-report-only и X-Frame-Options подходящих sub_frame host в panel tab, а не только frame-ancestors. |
| Постоянство доступа | Stop удаляет session/rules и выключает watch, но не отзывает host permissions и не unregister content scripts до конца browser session. |
| Origin/host | Session guard сравнивает hostname, permission match включает protocol, порт не отражён в match; не обещать полную origin-изоляцию по hostname. |
| Источник | Watch закреплён за normal-окном. Служебная страница/отсутствие доступа/закрытие наблюдаемого окна дают ожидание без чужого источника. Первичное восстановление со старыми ID может определить окно и сайт заново; сценарии восстановления требуют регрессии. |
| tabs | Чтение URL текущих вкладок согласовано пользователем. Это не доступ к DOM всех сайтов и не chrome.history; полный журнал посещений не сохраняется. |
| Две панели | Desktop-source хранит один token. Изоляция panelTabId/token и восстановление оставшегося источника при cleanup не обеспечивают одновременный replay двух панелей одного source. |
| DOM matching | Эвристика зависит от видимости, текста/селекторов/атрибутов; canvas, shadow DOM и разные desktop/mobile DOM могут вернуть missing. Нельзя нажимать произвольный элемент ради продолжения. |
| Навигация | Polling URL до 250 ms, история карточки пополняется на ready и route, но не хранит history.state/состояния форм. Back не равен Chrome history; автоподравнивание ограничено preparedOrigin. |
| Тайминги | До 80 pending events на карточку, readiness timeout 10/12 s. Ревизия операции защищает Stop/смену Main от поздних ответов, но не отменяет уже выполненные действия сайта. |
| Общий профиль | Cookies/авторизация общие по правилам Chrome, iframe cookies могут ограничиваться. Сайты и их аналитика загружаются как обычно; расширение её не блокирует. |
| Диагностика | Values полей не пишутся, URL/query/hash/selectors могут содержать чувствительные сведения. Экспорт проверить перед передачей. |
| Responsive | Собственный viewport 240..3840 CSS px в нейтральной тёмной рамке не имеет аппаратной диагонали. Drag пересчитывается через scale начала жеста и ограничивается диапазоном; сохранение после завершения. Физический масштаб заменяется обозначенным CSS 1:1, без обещания сантиметров. |
| Имитация устройств | CSS width/height и декоративный корпус не эмулируют OS, Safari, user agent или аппаратный DPR. |

## Main и синхронизация 2.6.13

Прежняя проблема «включение Main после независимого prepare не подключает источник» заменена resolver/watch/prepare. Выключенная синхронизация прекращает повторение действий, но Main продолжает следование адресу. Ручной адрес другого host требует пользовательского разрешения и navigate-source; пассивное переключение не вызывает prompt. Worker и панель должны согласовать protocolVersion:1: смесь загруженных версий нельзя диагностировать как сетевой сбой.

Prepare проверяет доступ/источник до замены правил, конфигурационная ошибка восстанавливает прежнюю session. Panel не должна очищать работающие iframe до успешной подготовки. Закрытие источника/служебная страница/потребность в доступе — ожидаемые состояния, не доказательство поломки сайта.

Ответ navigate-source может прийти после завершения загрузки вкладки. Состояние loading из такого ответа нельзя считать окончательным: требуется свежий resolver и восстановительная проверка раз в секунду только во время загрузки. События источника также переопределяют состояние через resolver. Индикатор учитывает c.ready/connectionFailed, а не один running: все экраны подключены — работа, часть недоступна — частичная готовность, ни один не подключён после таймаутов — ошибка подключения. Это не устанавливает сетевую причину или дефект сайта.

## Плотность, полосы и выделение

Для масштабированного iframe при host DPR < 2 применяется целочисленный zoom с обратным transform. CSS viewport и физическая геометрия сохраняются, но DPR дочернего документа меняется; srcset/resolution queries и потребление памяти могут измениться. CSS 1:1 оставляет исходную плотность. Это не гарантирует устранение размытия при дробном уменьшении.

Сообщённое размытие кнопок остаётся незакрытым дефектом. Для светлых углов найден конфликт специфичности внутренних скруглений .screen: поздний .device .display > .screen задаёт radius 0, общий clip/radius остаётся у .display. CSS viewport и формула физического масштаба не меняются. Сворачивание мобильных панелей меняет высоту сайта и может менять fixed/layout/cookie-banner; исправление углов не доказывает устранение размытия или всех наложений.

Host CSS запрещает выделение корпуса/iframe как единого синего объекта и служебных controls; ввод URL, pageurl, findings и QR-адрес допускают выделение. DOM встроенного сайта этим правилом не меняется, текст внутри сайта остаётся доступным для выделения. Это исправление выделения не объявляется исправлением графического размытия.

Зажатый pointer-жест отменяется на boundary/out/blur/visibility: capture освобождается, отправляются pointercancel/pointerup/mouseup, завершающий native click подавляется. Authenticated parent cancel-pointer — запасной путь только для данного iframe. Нестандартные виджеты могут игнорировать synthetic завершение; наличие этой отмены не гарантирует совместимость любых каруселей.

Закрытие error notice меняет только представление ошибки и сбрасывает видимый счётчик; причина и diagnostics не исчезают. Время относится к последнему отображению, счётчик — к одинаковому видимому сообщению, не ко всем сбоям за сеанс. Повторный сбой после dismiss снова должен показаться. Семантика missing ограничена подтверждённым этапом replay, не доказывает ошибку самого сайта.

Янтарное предупреждение missing и role=status отделены от состояния приложения; оно не должно выдавать работающий сеанс за остановленный. Блокирующий error имеет role=alert. Критические extensionUnavailable/extensionVersionMismatch/settingsReadFailed отражаются красным индикатором; исходное, рабочее, ожидающее и остановленное состояния различаются независимо от текста уведомления. Видимые подписи сеанса удалены по запросу пользователя, доступные aria/title/sr-only признаки сохранены.

Root scrollbar скрывается только у прямого iframe после handshake; nested scroll/дочерние iframe не меняются. Сайт может переопределить style. Wheel/keyboard/scroll relay сохраняются.

## Проверки и поставка

Scripts/check.cjs проверяет согласованные permissions/версии/синтаксис и запрещённые analytics signatures, но не заменяет полный анализ безопасности. CI существует; фактические настройки GitHub и результат конкретного remote run отдельно не подтверждены. Перед push обязательны локальные npm test/build и пользовательский commit pre-flight.

Для pointerup-only виджетов добавлено targeted завершение с defaultPrevented, защитой click/стандартного submit и recovery buttons:0. Прежняя фикстура, сбрасывавшая drag по cancel/mouseup, не покрывала этот класс. Новая регрессия сначала воспроизвела дефект. Публичную страницу со слайдером повторно прочитать не удалось; итог именно на пользовательском виджете остаётся неподтверждённым. Прямые fetch/location/form.submit и асинхронные site handlers не охвачены этой защитой.

Фокус iframe не равен потере фокуса приложения: parent blur не должен отменять новый click/drag дочерней страницы. Этот случай проверяется отдельно от настоящего window blur.

2.6.18: pendingSourceEvents хранит до 80 действий текущего источника на время loading resolver, со сбросом при смене session/URL/режима/контроллера. Это краткая очередь текущей страницы, не восстановление произвольной истории действий после перезапуска. Переполнение требует ручной проверки и показывает предупреждение. Source-navigate учитывает pendingUrl, чтобы не перезапускать уже начатый адрес; прочие ограничения нестандартных обработчиков сайта сохраняются.

Проверка вёрстки 2.6.19 учитывает прямоугольную overflow-обрезку/локальную прокрутку и paint containment, а не семантику конкретного слайдера. clip-path, mask, поворот/перспектива контейнеров, перекрытие соседними слоями, shadow DOM и содержимое вложенных cross-origin iframe не дают полной картины доступности. Полностью обрезанные элементы не сканируются, но потеря контента внутри намеренно обрезанного контейнера этим правилом не выявляется. Объединение вложенных overflow уменьшает шум, но не определяет CSS-причину автоматически; оставшиеся замечания требуют проверки. Результат относится к моменту сканирования; изменение размеров вызывает новую проверку, произвольные изменения DOM — нет.

Исключение iframe#ab в сканере ограничено точным hostname checks.botfaqtor.ru и полностью вынесенной за левый/верхний край служебной рамкой absolute/fixed. Оно не распространяется на все сторонние iframe или все элементы с id=ab. Это фильтр отчёта, не блокировка/интеграция стороннего сервиса.

## Магазинная подготовка 2.6.20

Устранён wildcard targetOrigin панели и добавлен входящий origin guard, с положительной регрессией и подтверждённым падением старого поведения. Состав store ZIP закрыт runtime allowlist и сверкой байтов. Это снижает риск утечки envelope/случайной упаковки внутренних файлов, но не является гарантией полной безопасности. Остаточные ограничения DNR, форм и URL в диагностике — store-security-review.md. Unlisted не ограничивает установку кругом сотрудников.


## Автоматизация магазина — локальная подготовка 2026-10-19

Store publisher fail-closed при неверной production-базе, чужом/параллельном кандидате, несовпадающих digest, warnings/takedown, отказе модерации и неизвестном результате write. Async upload без доказательства точной версии требует ручной сверки; нет слепого retry. Первый ручной bootstrap маркирует подтверждение оператора: CWS API не доказывает hash опубликованного ZIP. Signature scan не заменяет ротацию случайно опубликованных ранее секретов и не сканирует Git history автоматически.
