# Ручная диагностика

## Среда и версия

Для разработки нужны Node 22+, npm ci и Chromium Playwright. Разделяйте сбой запуска среды и дефект приложения. Перед push обязательны npm test и npm run build; результаты текущей проверки записаны в [checks.md](checks.md).

После обновления файлов обновите карточку на chrome://extensions, закройте старую панель и откройте заново. Простое обновление panel.html не перезагружает manifest/service worker. Несовместимый protocolVersion требует перезагрузить расширение, а не проверять сеть по предположению; текущая версия протокола — 1.

## Основная вкладка

«Основная» следует активной вкладке рабочего normal-окна, а не неизменному ID первоначального сайта. Стрелка фокусирует и вкладку, и окно. При выборе служебной страницы или закрытии сайта показывается ожидание, сохранённые экраны не очищаются. Другое окно не перехватывает источник.

Если закрыто уже наблюдаемое рабочее окно, ожидается unavailable без подмены чужим окном. Восстановление первоначальной панели со старыми ID отличается: активная панель может выбрать последнюю вкладку сайта того же normal-окна по lastAccessed либо ближайшему index.

При needs-access нажмите «Разрешить доступ»: разрешение на tabs позволяет прочитать адрес, но не заменяет host access. После перехода на новый домен доступ запрашивается отдельно. unknown-url означает, что Chrome не предоставил URL; это не доказательство ошибки сайта или сети. Полная история посещений не собирается.

Чтобы открыть новый адрес в основной вкладке, введите его и нажмите ▶. Для независимого просмотра снимите «Основная». Повторное ▶ должно применить встраивание даже при том же URL. При выключенной синхронизации Main продолжает следить за адресами, но не повторяет действия.

Если основная вкладка загрузилась, а сообщение о загрузке осталось, проверить фактический candidate через resolver. Ответ navigate-source может опоздать относительно tabs.onUpdated: его loading не должен заменять более свежий ready. В состоянии загрузки повторное разрешение источника выполняется раз в секунду; события ready/route/loading также вызывают resolver. Проверять окончательный URL и состояние вкладки, не только исчезновение сообщения.

Индикатор учитывает готовность встроенных экранов: все подключены — голубой; подключение или часть недоступных экранов — янтарный; после таймаутов нет ни одного подключённого — красный. Ожидание основной вкладки остаётся янтарным, явный Stop — приглушённо-красным. Наличие последнего предупреждения само по себе не меняет рабочий статус. Реально выполненные регрессии и их границы записываются в checks.md.

## Экран не подключается

1. Проверить фактическую версию панели/расширения и http/https URL без логина/пароля.
2. Проверить host permission, candidate state, адрес/окно источника и разрешение после redirect на другой домен.
3. Для сайта с запретом iframe включить «Разрешить встраивание» и нажать ▶; checkbox сам не меняет правило.
4. Сравнить ordinary tab и iframe, проверить worker/content script errors. Таймаут ready не доказывает CSP, сеть или несуществующий сайт.
5. Проверить Stop во время подключения/permission prompt: поздний ответ не должен возобновить показ. При смене Main во время подготовки итоговая сессия должна соответствовать новому режиму.

## Действия расходятся

Проверить sync, readiness, одинаковый URL без hash, активный экран и DOM-различия. missing означает неудачный match/unsupported replay, а не успешное выполнение. Выровнять по готовому лидеру/первому готовому экрану. Canvas/shadow DOM/custom controls проверяются отдельно; не отправлять формы на рабочих сайтах.

Диагностика содержит до 200 событий без values полей, но URL/selector могут быть чувствительными. Перед передачей проверить их; не создавать автоматические резервные копии отчётов.

Сопоставить действие/экран и reason сообщения: element-missing — соответствующий элемент не найден однозначно, different-page — разные страницы, apply-failed — ошибка повторения. Текст не должен повторно вкладывать уже сформулированную ошибку в другой такой же текст.

Крестик скрывает текущее сообщение, но не очищает diagnostics. Проверять счётчик только при видимом одинаковом тексте: повтор повышает число и обновляет время; после закрытия/clear новый сбой снова показывается с единицы. #sync-feedback содержит только сообщение, метаданные вынесены отдельно. Missing показывает янтарный role=status, блокирующая ошибка — role=alert; индикатор работающего приложения при missing остаётся голубым. Красный критический статус допустим для extensionUnavailable/extensionVersionMismatch/settingsReadFailed. Проверить title/aria-pressed и доступный sr-only #session-state после запуска, ожидания и Stop; видимых «Работает»/«Остановлено» пользователь не хочет. После Stop Play нейтрален, Stop приглушённо-красный.

Если карусель продолжает тянуться после возврата указателя, проверить отмену доверенного pointer-жеста на выходе за viewport/out/blur/visibility, освобождение capture и отсутствие завершающего native click. Запасная команда cancel-pointer от parent защищена существующим каналом и не зеркалируется. Проверять на локальной fixture; обычный свайп внутри и выделение текста должны сохраняться, нестандартный виджет может игнорировать синтетический pointercancel/mouseup.

## Размеры, размытие и наложения

Сравнить «На всю ширину», физические 100% и CSS 1:1, проверить масштаб Chrome и калибровку после смены монитора. Целочисленный zoom повышает плотность iframe, но не доказывает отсутствие размытия при дробном уменьшении.

Сообщённое пользователем размытие кнопок пока не объявлено исправленным. Отдельно найден и исправлен конфликт внутреннего border-radius .screen: поздний .device .display > .screen сбрасывает его, общий clip остаётся на .display. Проверять пиксели стыков/углов через tests/tablet-geometry.cjs, не менять viewport или калибровку ради оформления. Сворачивание панелей меняет высоту iframe и может менять fixed/cookie/layout сайта; найденный конфликт не объясняет автоматически все наложения.

Для «Отзывчивого устройства» проверить drag правой/нижней/угловой ручки тёмной рамки, диапазон 240..3840 CSS px, поворот и восстановление после rebuild/reload. Движение переводится в CSS px по исходному display scale, запись preferences выполняется один раз после завершения изменённого drag. Стрелки — шаг 1, Shift — 10. Числовые inputs ширины/высоты удалены; фактические размеры читаются в .dimensions. Оно без телефонных панелей; при физическом масштабе применяется явно обозначенный CSS 1:1, не аппаратная диагональ.

Root scrollbar скрывается после handshake только у прямого iframe. Колесо/клавиши остаются рабочими; nested scrollbars не скрываются. Auto должен вписываться после resize, CSS 1:1/физический масштаб могут требовать локальной прокрутки ряда. Не устранять это сокрытием overflow сайта.

## Очистка

Явный Stop выключает watch и удаляет panels/session rules; закрытие панели удаляет sourceWatches. Permissions и registered scripts остаются согласно контракту. Заголовки обычных вкладок не меняются. Для нескольких панелей одного source учитывать единственный token desktop-source; остановка одной не должна посылать глобальный stop оставшейся.

Для проверки отзыва откройте «Настройки → Доступ к сайтам». При перекрытии разрешений удаление одного pattern может сохранить доступ. После фактической утраты доступа исчезают рабочие iframe, source переходит в needs-access, session/rules очищаются; другие разрешённые сайты продолжают работать. Если Chrome отказал в remove, строка остаётся, показывается понятная ошибка.

Если номер сначала менялся 2.6.15 → 2.6.13, старый HTML показывал исходную версию до getManifest(). Теперь источник/загруженная версия сравниваются явно: при несовпадении показана рекомендация обновления карточки расширения, запуск остаётся доступен. Обновление одной панели не загружает новый manifest.
