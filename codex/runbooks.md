# Ручная диагностика

## Проверки разработки

Использовать Node 22+, npm ci и установленный Chromium. Если npm test не стартует, сначала проверить версию node и наличие devDependencies/browser, затем разделить npm run check, npm run test:integration и npm run test:desktop. На этом компьютере PATH ранее указывал Node 10; для статических проверок использован современный встроенный runtime. Ошибку запуска среды не считать дефектом синхронизации. Перед push требуется также npm run build; CI artifacts смотреть в Actions конкретного SHA. Не брать credentials/конфигурации из других проектов.

## Экран не подключается

1. Убедиться, что загружена папка extension и manifest показывает 2.6.1; при старой установке обновить карточку в chrome://extensions, закрыть и заново открыть panel.
2. Проверить http/https URL, выданный host access и соответствие домена источника адресу panel.
3. Для своего сайта с iframe restrictions включить compatibility и снова Показать; изменение checkbox само по себе правило не применяет.
4. Проверить redirect на другой host, ошибки service worker/content script и policy браузера. Таймаут означает отсутствие ready, а не автоматическое доказательство CSP-проблемы.

## Действия расходятся

Проверить sync и follow-source. При following действовать в основной вкладке. Проверить одинаковый URL без hash, готовность карточек и DOM-различия; missing означает неудачный match либо unsupported replay. Выровнять экраны вручную по готовому лидеру/первой карточке. Canvas, custom controls, shadow DOM и modal states проверить отдельно.

При необходимости сохранить диагностику кнопкой: отчёт до 200 событий, без values полей. Перед передачей другому человеку проверить URL/selector на чувствительные данные. Не создавать дополнительную копию отчёта или иной backup автоматически.

## Основная вкладка изменилась или закрылась

Другой домен: указать актуальный адрес и снова Показать, дать доступ. Закрытый источник: сообщение closed отключает following/running; для автономной проверки снова Показать. Background очищает связанные sessions. Если интерфейс остаётся в промежуточном состоянии, воспроизвести на тестовом сайте и проверить runtime errors.

Если после включения follow-source появляется «Нет подключённой основной вкладки», предыдущий prepare мог выполниться без источника. Проверить адрес основной вкладки, оставить follow-source включённым и повторно нажать «Показать». Переключатель сам не создаёт связь с источником.

## Проверка очистки

Stop/закрытие панели должны удалить её session rules и panels entry. Host permissions и registrations остаются согласно коду; это не критерий неудачной cleanup. Проверить, что ordinary tab headers не затронуты, source больше не зеркалируется. Изменение этой политики требует отдельной задачи.
