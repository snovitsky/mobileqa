# Интерфейс и поведение панели

У Play/Stop нет видимых надписей состояния. При работе Play голубой; после остановки он нейтрален, Stop выделен приглушённым красным (#744044). aria-pressed, доступные подписи и title сохранены.

Общий clip/radius принадлежит .display. Правило .device .display > .screen сбрасывает внутреннее скругление после старых model-specific правил: они ранее прорезали светлые углы у стыка сайта и панелей. CSS viewport, формула физической калибровки и масштаб iframe для этого исправления не меняются.

Зажатый pointer-жест внутри сайта отменяется при выходе за viewport, потере фокуса или скрытии страницы. Bridge освобождает pointer capture, отправляет pointercancel, отменённый pointerup и совместимый mouseup; завершающий click отменённого жеста подавляется до нового pointerdown. Родитель при pointerleave экрана/blur шлёт защищённый cancel-pointer как запасной путь. CSS и нормальное выделение текста сайта не отключаются. Нестандартные виджеты, игнорирующие синтетическое завершение, требуют отдельного воспроизведения.

## Текущее состояние 2.6.18

extension/panel.html — русскоязычная extension page, panel.js — ES module. В шапке URL, SVG ▶/■ (34 × 34 CSS px, title/aria-label), count 3/4/5, масштаб, «Синхронизация», «Основная», переход к источнику и меню настроек. Версия читается из manifest. Группы переносятся на узком окне; настройки имеют подсказки, доступные подписи и ограничение размеров меню.

Play/Stop отражают состояние сеанса через primary и aria-pressed, а #session-state сохраняет доступное состояние работы, остановки, подключения или ожидания без видимой текстовой подписи. После Stop голубое выделение Play снимается, квадрат показывает остановленное состояние даже при disabled. Цвет не является единственным признаком состояния.

Модуль extension/error-notice.js управляет #error-notice: точный текст сообщения остаётся в #sync-feedback, время последнего появления и число одинаковых срабатываний — отдельно в #error-notice-meta. Крестик скрывает сообщение; счётчик накапливается только пока виден тот же текст. Clear/dismiss сбрасывают его, следующий такой же сбой снова появляется с единицы. Это представление сообщения, не удаление diagnostics. Предупреждения повторения имеют янтарное оформление и role=status; блокирующие ошибки — role=alert.

Индикатор #status отражает состояние приложения отдельно от серьёзности уведомления: работа — голубой, остановка — приглушённый красный, ожидание/подключение — янтарный, исходное состояние — серый. Критические extensionUnavailable/extensionVersionMismatch/settingsReadFailed дают красный статус. Предупреждение missing не переводит работающий сеанс в красное состояние: баннер янтарный, рабочий индикатор остаётся голубым. #session-state имеет класс sr-only; видимые надписи «Работает»/«Остановлено» не выводятся, title и aria-pressed сохраняют смысл кнопок.

missing форматируется из kind/reason/eventId: действие, конкретный экран или основная вкладка, подтверждённая причина и следующий шаг. reason различает отсутствие соответствующего элемента, другую страницу и неудачный replay; длинные вложенные сообщения повторно не склеиваются.

Panel восстанавливает preferences до запуска. В Main включает watch-source и определяет фактическую активную вкладку закреплённого normal-окна; query source/sourceWindow — подсказки, не постоянная связь. Переключение в панель сохраняет известный источник, другое окно не перехватывает его. Закрытие вкладки, служебный URL и загрузка сохраняют прежние экраны; отсутствие доступа выделяется янтарным блоком с причиной и кнопкой. source-open активирует вкладку и фокусирует окно.

Если рабочее окно закрыто во время наблюдения, панель ждёт, не выбирает чужое окно. При первоначальном восстановлении со старыми ID активная панель может найти последнюю вкладку сайта того же normal-окна по lastAccessed, при отсутствии этого поля — по близости index.

Следование URL и повторение действий разделены: Main работает при sync off. При sync on действия зеркалируются между готовыми карточками и подключённым desktop source. Повторение действий выбирает leader; pending очищаются при pause/waiting. Явный ▶ запрашивает target-host access по пользовательскому жесту; в Main навигирует источник и принудительно применяет подготовку/настройку встраивания, в независимом режиме открывает URL экранов. Совпадение прежнего candidate не отменяет явное применение настроек.

Background prepare проверяет источник/доступ до замены session/rules. Panel заменяет iframe после успешного prepare с protocolVersion:1; ревизия операции защищает от поздних ответов после Stop/смены режима. Кнопка ■ прекращает наблюдение и сеанс, очищает экраны. Подробнее о guards и состояниях — [api-map.md](api-map.md).

Карточка хранит модель, ориентацию, CSS-размеры, URL, readiness, историю текущего сеанса и pending до 80 событий. Модели/landscapes/responsiveSizes восстанавливаются по позиции перед показом; существующие позиции сохраняются при rebuild. setURL создаёт remote src до вставки iframe, sandbox allow-scripts/allow-same-origin/allow-forms/allow-modals/allow-downloads, referrerpolicy strict-origin-when-cross-origin. Таймаут 10/12 секунд показывает отсутствие ready, не устанавливает причину.

## Собственный viewport

«Отзывчивое устройство» управляется extension/responsive.js: ширина/высота 240..3840 CSS px, канонические responsiveSizes[i] = {width,height}, отдельный landscape. У него нейтральная тёмная скруглённая рамка без телефонных вырезов/мобильных панелей/аппаратной диагонали; профиль исключён из калибровки. При физическом общем scale используется CSS 1:1 (жирным, с прежним цветом текста).

Размер меняется ручками на правой/нижней границе и в углу. Числовых полей «Ширина»/«Высота» нет; фактические размеры доступны для чтения в .dimensions. Drag использует pointer capture и масштаб отображения, измеренный в начале жеста, для перевода движения указателя в CSS px. Значения округляются/ограничиваются 240..3840 и переводятся в каноническую ориентацию. Во время движения callback вызывает перерасчёт с save:false; по завершении изменённого жеста сохраняет один раз с save:true. Стрелки клавиатуры на ручке меняют размер на 1 CSS px, Shift — на 10. Размеры и landscape сохраняются при rebuild/reload.

## Масштаб и контроль состояния

DEVICES задают полный прямоугольник дисплея, hardware/browser chrome уменьшают высоту сайта внутри полного дисплея. Auto вычитает фактические gaps/padding/оболочки, минимальный scale 0.01; ResizeObserver отслеживает ширину ряда. CSS 1:1 и физические масштабы допускают прокрутку #devices. Для аппаратных профилей физический масштаб использует diagonalInches × 25.4 × pxPerMM × savedDPR/currentDPR / hypot(width,height).

При уменьшении на host DPR < 2 используется целочисленный iframe zoom с обратным transform, CSS 1:1 без увеличения плотности. Это может менять iframe DPR/srcset/resolution queries; аппаратный DPR модели не эмулируется. Bridge скрывает только root scrollbar прямого iframe после handshake, не scroll как действие и не вложенные полосы.

«Назад» использует локальную navigationHistory, а не chrome history. Reload/Back распространяются между карточками при sync on. QR генерируется локально; HTTP-статусы и DOM-замечания привязаны к iframe/token/URL. Snapshot каждые 1200 ms проверяет расхождение URL/modal состояния готовых карточек с порогами 2500/1800 ms; это не доказательство совпадения всего DOM с desktop.

Размытие кнопок на пользовательском сайте остаётся незакрытым. Для светлых внутренних углов найден и исправлен отдельный конфликт специфичности: поздний .device .display > .screen задаёт border-radius:0, общий clip/radius остаётся у .display. Изменение высоты viewport при сворачивании штатно; исправление углов не объявляется устранением размытия или всех возможных наложений.

Для отдельного дефекта выделения host CSS задаёт user-select:none служебной шапке/подписям/корпусу/iframe и controls; для URL input, pageurl, findings и QR-адреса возвращает user-select:text. DOM удалённого сайта не меняется: его текст остаётся выделяемым. Это предотвращает синее выделение iframe как объекта, но не означает исправление графического размытия или всех наложений.

## Исправления отображения 2.6.10

Шапка переносит группы вместо прежнего принудительного nowrap/overflow-x:auto. Настройки содержат title, aria-describedby и видимые пояснения; селекты/флажки/стрелка основной вкладки оформлены явно, с fallback forced-colors. Фокус поля URL рисуется внутри границы. Меню позиционируется относительно summary с ограничением ширины окна; после resize его положение пересчитывается.

Auto-scale берёт фактический column-gap и padding ряда #devices, оставляет боковой запас по 4 px для кнопок корпуса и обводки. Минимум auto 0.01 вместо 0.1 позволяет вписать ряд в узкое окно. ResizeObserver следит только за изменением ширины #devices: появление вертикальной полосы окна больше не оставляет старый масштаб. CSS 1:1 и калиброванные масштабы допускают локальный горизонтальный скролл ряда.

В resize() сначала назначаются прежние целочисленные width/height iframe. Для масштабированного вида при host devicePixelRatio < 2 задаётся целочисленный zoom=2 и transform=scale(viewScale/2); иначе zoom=1 и scale(viewScale). Дробный zoom напрямую не используется: он округляет фактический CSS viewport. На всех ветках сохраняются геометрия display, CSS width/height и формула калибровки. CSS 1:1 использует zoom=1. Увеличенная плотность — технический способ отрисовки, не аппаратная эмуляция; iframe devicePixelRatio и resolution media queries могут измениться.

Bridge после enabled handshake добавляет style для :root/body с scrollbar-width:none и ::-webkit-scrollbar. Изменение применяется только когда непосредственный ancestor origin совпадает с проверенным parentOrigin панели; child iframe сайта и top-frame источника остаются без изменения. Overflow не отключается, вложенные прокручиваемые блоки сохраняют оформление.

## Восстановление панели 2.6.11

После чтения preferences и displayCalibration, до build/автозапуска, восстанавливаются count, scale, sync и followSource. Пользовательские изменения сохраняются в chrome.storage.local; подтверждённая калибровка тоже сохраняет итоговый scale. lastScale инициализируется восстановленным значением, поэтому отмена следующей калибровки возвращает именно его. Не подтверждённый физический масштаб не записывается.

Форматы runtime не меняются; sync передаётся в prepare уже восстановленным. Ошибки записи preferences показываются через status.


## Контекст ошибок и поворот 2.6.12

reportError выводит только userMessage из errors.js и пишет в диагностику код без сырых исключений. Разделены ввод URL, основная вкладка, разрешения, связь с background, запуск/остановка, чтение/запись preferences, калибровка и QR. Неизвестная причина не объявляется отсутствием поддержки элемента или сетевой ошибкой сайта. Timeout означает отсутствие подключения, а не доказанную блокировку сайта. HTTP status=0 означает, что браузер не сообщил статус, а не дефект сайта.

Поле адреса проверяется приложением (form.noValidate), поэтому пустой/неразбираемый/служебный/содержащий credentials URL получает русский текст с действием. При ошибке чтения настроек строится панель с defaults, но автозапуск блокируется, чтобы случайно не включить ранее отключённую синхронизацию. Ошибка записи не подменяется успешным сообщением калибровки. Проверки без подключённой страницы и QR/выравнивание дают явное объяснение.

landscapes восстанавливаются после build вместе с devices; кнопка поворота сохраняет preferences. Пересборка количества сохраняет ориентации существующих карточек. Селекты моделей и диалога калибровки получают такие же размер/отступ стрелки, как controls шапки, с отдельным цветом для светлой темы.

## Hover/focus

Состояния наведения и клавиатурного фокуса унифицированы для шапки, моделей экранов, кнопок карточек, настроек, QR/калибровки и справки. Старое зелёное кольцо с большим внешним отступом удалено. Фокус остаётся заметным, компактным и не перекрывает соседние элементы; disabled controls не получают активное оформление, forced-colors использует системные цвета.

Коды HTTP показаны с пояснением: 401 — требуется вход, 403 — сайт отказал в доступе, 404 — страница не найдена, 5xx — сайт сообщил об ошибке сервера. Технический номер сохранён для разработчика, но не заменяет дальнейшее действие для пользователя.

Во время изменения responsive-рамки временный прозрачный shield на уровне панели не даёт cross-origin iframe перехватывать поток мыши. Он существует только для активного жеста и удаляется на pointerup/cancel, потерю capture, blur или Escape. Модуль фокусирует ручку без прокрутки, слушатели жеста удаляются вместе со shield; обычные клики и выделение сайта не меняются.

## Уточнение состояния и интерфейса 2.6.15

После navigate-source панель заново вызывает resolve-source: ответ о начале перехода может прийти после complete. Пока sourceCandidate имеет loading, работает одиночная повторная проверка через 1 секунду; ready/route/loading от текущего desktop token также инициируют resolver. Ревизия защищает от устаревшего ответа, Stop/выключение Main отменяют ожидание. Для iframe без ready панель раз в секунду отправляет защищённый ping: это восстанавливает состояние после отменённого beforeunload.

Общий индикатор учитывает ready и connectionFailed карточек: все подключены — running/голубой; подключение — loading/янтарный; после таймаута часть подключена — partial/янтарный; ни одного — disconnected/красный. Main waiting и Stop имеют прежнюю семантику. Текст ошибки сам по себе не определяет цвет. Это статус подключения, не проверка бизнес-логики сайта.

Needs-access — заметный янтарный блок с замком, заголовком «Нужен доступ к сайту», причиной и кнопкой разрешения. Автоматического запроса доступа нет. Постоянные пояснения настроек скрыты через sr-only и aria-describedby, сведения доступны в title при наведении. У responsive убраны постоянные подсказки про край/угол и калибровку; CSS 1:1 жирный, цвет наследуется.

При смене числа экранов сохраняются фактические URL прежних карточек; черновик адресной строки не запускается. История карточки учитывает ready и SPA route, поэтому «Назад» возвращает предыдущий зафиксированный адрес, но не восстанавливает состояние history.state/форм. Matching внутри общей ссылки сначала проверяет признаки самого элемента; равные по рейтингу кандидаты дают missing.

## Управление доступами 2.6.15

Модуль access-settings.js экспортирует setupSiteAccess({container,onError,onRevoked}) → {refresh,dispose}; владеет details#site-access в меню. Получает patterns непосредственно из Chrome, сортирует и безопасно выводит textContent, удаляет по явному клику, обновляется при открытии и onAdded/onRemoved. Ревизия чтения защищает список от устаревшего ответа. Постоянных пояснений нет, title объясняет действие. Ошибка чтения/отзыва получает код siteAccessReadFailed/siteAccessRevokeFailed; кнопка блокируется только на время операции.

После access-revoked sessionRevoked:true панель инвалидирует operation/sourceRevision, обнуляет token, выключает running, очищает iframe и очереди. При false обновляет только список, сохраняя работающие страницы. Наружный click определяется через composedPath, чтобы удаление строки после отзыва не закрывало меню.

## Версия и читаемые адреса

В HTML #version первоначально содержит «…», data-source-version хранит версию файлов. Панель показывает только chrome.runtime.getManifest().version, без мигания номера исходников. Если номера различаются, показывает оба и спокойную рекомендацию chrome://extensions → обновить карточку → открыть панель. Разница номеров не блокирует auto-start, ▶ или Main, не меняет рабочий индикатор и не считается ошибкой. #update-notice существует отдельно от ошибок и может быть скрыт крестиком. Перезагрузка HTML-панели не считается обновлением загруженного manifest. scripts/check.cjs сравнивает data-source-version с package/manifest.

url-display.js декодирует Punycode только для читаемого представления hostname в списке доступов. Scheme/path/query/hash/wildcard/port не меняются; исходный ASCII pattern доступен в title и неизменно используется permissions.remove. Невалидный label возвращает исходную строку. Это представление, не новая канонизация или проверка домена. Алгоритм сверялся с RFC 3492 (https://www.rfc-editor.org/rfc/rfc3492) и тестовым oracle node:punycode.

Повторное исследование drag 2.6.15: cancelPointer дополнительно отправляет defaultPrevented pointerup и mouseup с buttons:0 после освобождения capture. Во время cleanup блокируются click и стандартный submit/requestSubmit, включая .click из синхронного release-handler; последующее native завершение отменённого жеста подавляется до нового pointerdown. Mouse pointermove с buttons:0 восстанавливает пропущенный up. Это не защита от произвольного direct fetch/location/form.submit сайта и не аппаратная эмуляция.

Отзыв текущего доступа дополнительно проверяется самой панелью по permissions.contains на onRemoved/успешном UI remove. Если загруженный старый worker ещё не отправляет access-revoked, панель инвалидирует документы/token и вызывает прежнюю команду stop. Перекрывающийся grant сохраняет сеанс. Это не подмена номера версии и не снятие реальных protocol/API guards.

При принятии authoritative source candidate loading/ready прежний leader карточки сбрасывается перед setURL: поздний ready/route от ранее управлявшего телефона не должен навигировать источник обратно на старый адрес. Desktop регрессия проверяет передачу controller источнику и обычный следующий phone intent.

Blur окна панели проверяется после перехода фокуса: document.hasFocus() остаётся true при фокусе внутри iframe. Такой переход не посылает cancel-pointer всем карточкам. Реальная потеря фокуса приложения сохраняет fallback отмены. UI-regressions удерживает кнопку мыши после перехода URL→iframe и проверяет trusted click при DPR 1/1.25/2.

## Встроенные редакторы 2.6.16

renderResponsiveDimensions в responsive.js показывает строку как кнопки-числа без рамок. Только при редактировании число заменяется временным input: Enter/blur подтверждают корректный ввод, Escape отменяет; неверный Enter показывает validation hint, неверный blur возвращает прежнее число. Изменение ширины панели не уничтожает открытый редактор. Размеры вводятся в видимой ориентации и сохраняются канонически; handle drag и строка используют один callback.

responsiveScale — null (унаследованный режим) либо ratio 0.01..2. Явный масштаб имеет приоритет только у responsive, не меняет CSS viewport. В auto ширина явно масштабированных responsive заранее вычитается из доступной строки; остальные устройства делят остаток. Избыточный пользовательский процент допускает прокрутку. UI всегда показывает фактический процент, жирным и прежним цветом; 100% — CSS 1:1. Аппаратная калибровка не менялась.


## Отчёт проверки вёрстки 2.6.17

inspection-report.js отображает результаты по трём категориям: переполнение, маленькие области нажатия, мелкий текст. Секции свёрнуты, CSS-пути скрыты в «Для разработчика». Имя элемента содержит тип и короткий текст/aria-label/alt/placeholder, без чтения value. Кнопка элемента прокручивает соответствующую карточку и отправляет show-finding только её iframe. Bridge прокручивает элемент и подсвечивает его на 4 секунды overlay с закрытым shadow root и pointer-events:none; стиль и обработчики элемента не меняются, click/focus не вызываются. Программная прокрутка исключена из relay через mute.

«Скачать отчёт» объединяет одинаковые описания и измерения в одну запись со списком элементов и создаёт локальный TXT с группами, адресом, моделью, фактическим CSS viewport, временем, описаниями и селекторами. Отчёт привязан к моменту сканирования. Если DOM изменился, используется сохранённая ссылка на элемент, а не поиск похожего: удалённый/скрытый элемент даёт предложение повторить проверку. Сканирование ограничено 10 000 элементами и 200 замечаниями; превышение явно обозначено. Это эвристики для ручной проверки, а не подтверждённые нарушения стандартов.

## Встроенное руководство для первого запуска

В footer панели — краткое назначение приложения, три видимых шага (адрес/доступ, модели/общий масштаб, действия/синхронизация) и десять свёрнутых тем. Они объясняют Play/Stop/индикатор, независимость Main и Sync, inline-размеры/процент responsive, отличие CSS 1:1 от физической калибровки, кнопки карточки/QR, отчёт/подсветку, устранение проблем, сохранение и отзыв доступа, остальные настройки и границы макетов. Desktop — три колонки шагов и две колонки ответов; узкий экран — одна колонка. Калибровка не предлагается как обязательный шаг обычной проверки. Runtime и permissions этим изменением не меняются.

FAQ расположен в двух независимых .guide-column: раскрытие ответа не увеличивает интервалы в соседней колонке. Первые пять тем — начало работы, вторые пять — отчёты/проблемы/доступ/настройки/ограничения. На узком экране колонки идут последовательно.


## Действия источника во время проверки загрузки: 2.6.18

Первый trusted click/input после reload мог прийти раньше resolver ready и отбрасывался по sourceConnected=false. Такие действия текущей session теперь ожидают в pendingSourceEvents при loading, а не считаются непригодными навсегда. После подтверждения того же источника/URL они передаются через relay; token/URL/session и Sync проверяются повторно. Очередь не даёт разрешения повторять действия чужой вкладки/страницы, отменяется при Stop, выключении Main/Sync, отзыве доступа, смене источника/токена или управляющего макета. Лимит 80 и coalescing scroll ограничивают память. Никаких дополнительных запросов доступа нет.

## Проверка геометрии 2.6.19

Сканер каждого iframe пересекает прямоугольник элемента с областями обрезки предков: overflow hidden/clip/auto/scroll по соответствующей оси и paint containment. Учитываются border/client-размеры и масштаб прямоугольных контейнеров. Полностью обрезанные элементы исключаются из всех трёх правил; вертикальная граница самого viewport не ограничивает проверку содержимого ниже первого экрана. Названия библиотек/классы слайдеров не используются как исключения. Видимые части контейнеров и самостоятельные переполнения остаются в отчёте, включая левый край и fixed. Описание содержит сторону, величину переполнения и ширину viewport в CSS px; горизонтальная прокрутка документа не превращает видимые fixed-кнопки в переполнение.

Вложенные элементы с тем же переполнением объединяются под ближайшим подходящим предком; relatedCount показывает число объединённых элементов. Если потомок выходит дальше предка, он остаётся самостоятельным кандидатом. Общая запись scrollWidth страницы используется только при отсутствии найденных элементов (например, источник в псевдоэлементе). Переполнения выдаются перед target/text, общий лимит 200 сохранён.

Смена модели, поворот, browser chrome или CSS-размеров сразу скрывает старый отчёт; при включённой проверке через 300 ms после последнего изменения запрашивается новый. Изменение одного визуального масштаба без изменения CSS viewport не требует пересканирования. Приём page-findings сверяет source/token/URL и фактический viewport с текущими размерами iframe; запоздалый результат старых размеров отбрасывается. Произвольные изменения DOM/анимации после сканирования требуют повторного поиска.

В той же 2.6.19 кнопка запуска показывает ▶ до запуска/после Stop и ↻ при существующем сеансе (в том числе во время повторного подключения). Состояние primary/aria-pressed и индикатора не менялось. SVG path, title и aria-label меняются совместно. Повторный submit по-прежнему заново открывает макеты по URL строки; при включённой «Основная» сохраняется прежнее следование/переход основной вкладки. Это не обычный location.reload каждого текущего различающегося адреса.

Точечное исключение сканера: iframe с id=ab, hostname checks.botfaqtor.ru, absolute/fixed и полностью вынесенный левее/выше −1000 CSS px. На пользовательской странице пассивно подтверждены src https://checks.botfaqtor.ru/, размеры 300×150 и left/top −9999. Видимый iframe, иной hostname или иной id не получают этого исключения; DOM сайта не удаляется и источник iframe не изменяется.
