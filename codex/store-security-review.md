# Проверка подготовки магазинного выпуска — 2026-10-19

Security result: allowed with conditions

Это результат локальной проверки исходников и кандидата 2.6.20, а не разрешение на публикацию и не подтверждение отсутствия любых уязвимостей. Фактический магазин, Google Cloud и настройки GitHub production-доступа не проверены и не настроены.

## Профиль проекта и стек

SECURITY_REVIEW_PROFILE.md и .security-review/profile.md отсутствуют. Проверялись весь extension/, scripts/, tests/, manifest/package/lockfile, workflow и документация; runtime не содержит npm-зависимостей. Сторонний QR-код включён локально с MIT license. Сервер, БД, платежи, инфраструктура TLS/DNS и пользовательская система авторизации отсутствуют: серверные разделы аудита неприменимы.

Стек — Chrome MV3, native JavaScript ES modules, HTML/CSS; Node 22+, Playwright/fflate только для разработки. Это приемлемо для небольшого расширения; переписывание на серверный framework не требуется. TypeScript/SCSS/BEM не используются: это ограничение поддержки типов/стилей, а не доказанная уязвимость. Предпочтительно постепенно улучшать читаемость плотного panel.js и повторяющихся CSS, отдельно от функционального выпуска.

## Что проверено

Границы runtime/sendMessage и postMessage, источник/токен/состояние сообщений, выдача/отзыв host access, scope DNR, нормализация URL, password/file guards, хранение preferences/session, скачивание отчётов/диагностики, DOM sinks панели, исполняемые ресурсы, сборка и состав ZIP, зависимости и CI. Код собственного расширения не загружает исполняемый JavaScript с внешнего сервера. Проверка геометрии эвристическая; реальные сайты могут менять DOM и состояние после сканирования.

## Критические блокеры

В проверенном коде подтверждённых открытых Critical-находок не выявлено. Это не формальная верификация Chrome или чужих сайтов.

## Высокие риски

**High, исправлено локально до публикации:** panel ранее отправлял сообщения iframe с targetOrigin='*', а входящие сообщения не проверяли e.origin. Likelihood: medium; impact: после навигации iframe на иной origin тот мог получить служебный envelope и попытаться отправить сообщения от имени сеанса. Простыми словами: сменившая сайт рамка не должна получать команды прежнего сайта. Исправление — точный preparedOrigin в обе стороны. Регрессия message-origin.cjs прошла; при временном возврате старого поведения тот же тест обнаружил утечку envelope. Приоритет: до production; исправление ещё не отправлено пользователям.

## Средние риски

- **Medium, остаточный:** compatibility снимает всю CSP/CSP-report-only/X-Frame-Options для ответов sub_frame выбранного host в panel tab. Likelihood: medium, impact: ослабление политик самого сайта внутри макетов. Scope и очистка проверяются тестами; обычные вкладки правило не затрагивает. Владелец продукта должен учитывать это при выпуске; описано в privacy/access/user-guide. Возможное изменение default встраивания — отдельное решение, не незаметная правка этой задачи.
- **Medium, остаточный:** синхронизация обычных полей и действий работает в реальной браузерной авторизации. Likelihood: medium, impact: повторная отправка пользовательского действия или перенос чувствительного значения между макетами. Password/file исключены штатными guards, но нестандартные редакторы и обработчики сайта требуют ручной осторожности. Не добавлены внешняя телеметрия или автоматические рабочие формы.
- **Medium, остаточный:** диагностика/отчёты содержат URL, в том числе query/hash, и обозначения элементов. Likelihood: medium, impact: пользователь может сам переслать чувствительный адрес. Экспорт только по команде, автоматической отправки нет; перед пересылкой нужна проверка. Не заявлять полную анонимизацию.

## Низкие риски и hardening

Из manifest удалено избыточное activeTab; tabs, storage, scripting и declarativeNetRequestWithHostAccess сохранены по назначению. Optional HTTP/HTTPS scopes не расширялись. Необходимость tabs ранее явно согласована владельцем. Адресные подсказки используют только concrete grants из permissions.getAll, не history API.

Сигнатурный аудит пакета не заменяет доказательства отсутствия любого секрета. Он проверяет известные форматы, локальные imports и точный allowlist; проверенные файлы также сверялись с исходниками. В store ZIP нет внутренних документов, тестов, devDependencies, рабочего лога и конфигураций доступа.

## Бизнес-логика

Проверены переключатели Main/Sync, остановка и отзыв разрешений, смена origin, повторение событий и отмена жеста. Ролей/платежей/заказов в приложении нет. Unlisted не является авторизацией: установить сможет любой с магазинной ссылкой. Будущий CI publisher получает доступ уровня издателя, поэтому WIF должен ограничиваться конкретным репозиторием/production-ref.

## Проверки

Реальные команды и результаты записаны в [checks.md](checks.md). Выполнены локальные browser regression tests и аудит ZIP; npm audit сообщил 0 известных уязвимостей зависимостей на момент проверки. Это не результат проверки модератора магазина.

Не выполнены: текущий Ubuntu CI для незакоммиченного кандидата, первоначальная магазинная установка/обновление, реальное подключение production API/WIF, проверка аккаунта и финальной карточки. У прежнего CI 2.6.19 был нестабильный focus-тест: повтор того же SHA прошёл, первопричина не объявляется устранённой. Реализация API-клиента и lifecycle проверена изолированными fixture; это не подтверждение реальных прав в аккаунте.

## Откат и условия production

Дополнительные резервные копии не создавались. Для магазинного возврата к рабочему поведению нужен новый выпуск с большим номером, подготовленный из рабочего source SHA; нельзя рассчитывать на мгновенный downgrade. Данные сервера/БД не меняются.

До автоматического production: закончить карточку/политику/графику, подтвердить пакет и остаточные ограничения, обеспечить воспроизводимость CI, подключить к аккаунту и испытать подготовленные publish/monitor с production notes. План — [store-release-plan.md](store-release-plan.md). Исправления origin и состава ZIP должны войти в первый публикуемый пакет.

Остаточный риск: поведение сторонних сайтов, cookies/авторизация, нестандартные формы, DOM после сканирования, особенности разных версий Chrome и решение модератора. Локальное прохождение тестов не устраняет эти ограничения.

## Дополнительная проверка доступов и CI

По запросу владельца выполнен redacted-поиск Yandex OAuth, Google/GitHub/AWS ключей, JWT, приватных ключей и literal credentials в текущем репозитории, включая рабочие текстовые файлы вне package allowlist. Отдельно проверены все текстовые файлы точного store ZIP. Сигнатур доступов не найдено; обращения к API Метрики отсутствуют в runtime. Не использовались другие проекты, системные конфигурации, браузерные хранилища секретов или история Git. Значения совпадений scanner не выводит. Неизвестный формат секрета или простое произвольное значение без распознаваемого контекста сигнатурный поиск может пропустить.

CI теперь выполняет этот поиск до сборки. Пакет сверяется без вывода исходных byte buffers при несовпадении. OIDC только main environment; staging/PR запускают все те же проверки, но publisher token не получают. Краткоживущие CWS_ACCESS_TOKEN/GH_TOKEN берутся из Actions, имена env/expressions в workflow не являются сохранёнными значениями ключей. Ни Google JSON-key, ни access token не входят в runtime allowlist.

Publisher фиксирует точный SHA/digest проверенного artifact, отказывает при неверной production-базе/конфликте тегов/другом кандидате и не повторяет write при неизвестном результате. Первая ручная публикация может быть связана с provenance только отдельным операторским bootstrap; это явно не API-доказательство байтов пакета. Все эти ограничения остаются условиями первого действующего выпуска.
