# Правила проекта Mobile QA Basic

- Сохранять версию Basic без Метрики и данных клиентов.
- Начинать задачу в отдельной ветке codex/ от актуального main. Не пушить main напрямую и не использовать force push.
- Изменения публиковать PR; не объединять собственный PR без явного разрешения пользователя. Человеческую проверку не заменять самопроверкой агента.
- Перед PR запускать npm test и npm run build; сообщать о реально выполненных проверках и ограничениях.
- Не расширять permissions или optional_host_permissions без явной инструкции пользователя. Соблюдать docs/PROTOCOL.md.
- Не отправлять формы и цели на рабочих сайтах в автоматических тестах. Использовать локальные фикстуры и отдельный профиль Chromium.
- Не добавлять секреты, .env, клиентские выгрузки, абсолютные пути компьютера в код или тесты.
- Крупный рефакторинг выполнять отдельным PR; не смешивать его с функциональными изменениями. Согласовывать пересекающиеся задачи в Issue.
- Правила совместной разработки: CONTRIBUTING.md. Общение — по-русски; английские сообщения пользователя проверять как репетитор.
