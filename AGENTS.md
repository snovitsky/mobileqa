# Правила проекта Mobile QA Basic

- Проект предназначен только для проверки сайтов и синхронизации экранов. Не добавлять интеграцию с Метрикой, внешними API или данные клиентов.
- Не искать и не использовать доступы из других проектов, прежних папок разработки, системных конфигураций или истории чатов. Не переносить в проект ссылки на такие источники.
- Работать только в main. Перед изменениями получать актуальный main; отправлять изменения напрямую в main. Не использовать force push.
- Отдельные ветки и обязательные PR не использовать. Согласовывать пересекающиеся изменения с программистом.
- Перед push запускать npm test и npm run build; сообщать о реально выполненных проверках и ограничениях.
- Не расширять permissions или optional_host_permissions без явной инструкции пользователя. Соблюдать codex/api-map.md.
- Не отправлять формы и цели на рабочих сайтах в автоматических тестах. Использовать локальные фикстуры и отдельный профиль Chromium.
- Не добавлять секреты, .env, клиентские выгрузки, абсолютные пути компьютера в код или тесты.
- Крупный рефакторинг выполнять отдельным коммитом; не смешивать его с функциональными изменениями. Согласовывать пересекающиеся задачи в Issue.
- Правила совместной разработки: codex/workflow.md. Общение — по-русски; английские сообщения пользователя проверять как репетитор.

# Работа с Mobile QA Basic

Сначала читать [codex/README.md](codex/README.md), затем профиль задачи по [индексу](codex/context-index.md). Документация на русском языке. Факты проверять по исходникам; неизвестное записывать в `codex/open-questions.md`.

## Правила пользователя

- Сообщения коммитов на русском языке в формате Conventional Commits: `type: краткое описание`.
- Перед каждым коммитом показать commit pre-flight: текущий git status, точный список файлов, резюме изменений, сообщение коммита и результаты проверок. Дождаться явного подтверждения. Посторонние изменения указать отдельно и не включать без отдельного разрешения.
- Не создавать дополнительные резервные копии файлов, конфигураций и БД, включая dump/gzip/bak/before/snapshot. Использовать штатные сохранённые releases, если они существуют; при изменении данных применять guards, transaction и readback. Существующие копии удалять только в явно разрешённой области после проверки точных путей.
- В Windows сетевые Git-команды по HTTPS сразу выполнять через `exec_command` с `sandbox_permissions="require_escalated"` и конкретным обоснованием, без предварительной попытки внутри песочницы. Это выбор среды, а не разрешение на push или другие изменения. Локальные Git-команды выполнять обычным способом; отказ разрешений не обходить.

## Границы проекта

Это Chrome Manifest V3 extension в `extension/`, без backend и сторонних runtime-библиотек. Для разработки нужны Node.js 22+, devDependencies Playwright/fflate; доступны браузерные тесты, ZIP-сборка и CI. Установка — загрузка распакованной папки `extension/`. Не превращать CSS viewport в обещание аппаратной эмуляции. Basic сохраняется без внешних интеграций.

Перед изменениями синхронизации читать `codex/api-map.md` и `codex/risk-zones.md`; при изменении разрешений — `codex/access.md`. Не считать README доказательством защиты: известное ограничение password описано в документации и должно проверяться по коду.
