# Совместная разработка

Каждая задача начинается с Issue: проблема, ожидаемый результат, способ проверки и исполнитель. Один Issue — один основной исполнитель. Если нужны одни и те же файлы, согласуйте границы работы в Issue до начала правок.

Работайте в собственном клоне, только в main. Перед задачей выполняйте git pull --ff-only. Не используйте одну общую рабочую папку для двух исполнителей. Изменения отправляйте напрямую в main без force push. Если main обновился во время работы, сначала получите изменения и согласуйте конфликты.

Установка: Node.js 22+, `npm ci`, `npx playwright install chromium`. На Linux для системных зависимостей используйте `npx playwright install --with-deps chromium`. Затем `npm test` и `npm run build`. Тесты используют отдельные временные профили Chromium и только локальные страницы; не отправляйте тестовые заявки на клиентские сайты.

Установка расширения для ручной проверки: chrome://extensions → режим разработчика → загрузить папку extension/. После правок нажмите «Обновить» и откройте панель заново.

Перед отправкой изменений запускайте npm test и npm run build. Делайте небольшие понятные коммиты с описанием результата. Один участник работает над согласованной задачей; второй не меняет те же файлы одновременно. Проверку коллегой можно выполнять по коммитам.

Не меняйте разрешения, протокол сообщений и обработку форм без описания причины и тестов. Сначала отдельно выполните крупный рефакторинг, затем распределяйте задачи по модулям. Не смешивайте перемещение кода с новой функциональностью в одном коммите.

Basic остаётся без интеграции с аналитикой. Не коммитьте токены, .env, клиентские выгрузки и персональные данные. Репозиторий публичный. ZIP создаётся из разрешённого списка файлов extension/, не из всей рабочей папки. Версию меняйте одновременно в package.json и extension/manifest.json в отдельном релизном изменении; lock-файл обновляется npm install --package-lock-only. Используйте теги vX.Y.Z для согласованных релизов. Архив CI доступен в Actions у соответствующего коммита; его имя содержит SHA.

Main допускает прямые push. По подтверждению владельца обязательные PR, ревью и проверки перед push отключены. CI/checks продолжает запускаться после каждого push в main. Force push и удаление main запрещены.
